per block or movement tick. Across the retained trials: **40 returned calls**, one
additional started/canceled call, returned latency **3.370–33.517 seconds**, median
**4.931 seconds**. Reported usage totals **587,807 input**, **266,112 cached input**
(a subset of input) and **3,322 output tokens**. The canceled call's usage is unknown,
not zero; its measured duration was 0.526 seconds. No billing estimate is claimed.

Stop took **307.685 ms** from the application's logged request to stationary-position
confirmation. This is observed cessation, not a special server Stop acknowledgment.
The retained cancellation proof finds zero child submissions before the next
explicit user request. Synthetic delayed-provider and child-boundary tests also
check late replies/results independently of live subprocess cancellation.

Initial trials experienced much longer scheduling/CLI delays: the first Survival
request took 86.819 seconds to first child, and the first Creative return took
63.169 seconds. Server logs observed during that period reported substantial tick
lag; the exact cause of the connection failure was not established. Later complete
runs above are reported separately, without erasing slow trials or claiming an
across-the-board latency improvement. Context trimming removes recursive inference
records and limits model resource observations to 24; the runtime still inspects
up to 64 candidates.

## Retained unsuccessful trials and corrections

1. First natural Survival request asked for three additional logs, collected two
   birch logs and returned. An overly broad underfoot/overhead check rejected safe
   overhead logs; a subsequent route attempt failed. Corrected the check to retain
   the prohibition on digging below the bot, plus reach and line-of-sight checks.
   Its concurrent question finished after the goal; it does not establish overlap.
2. An eight-log request was rejected as `not_ready` after a connection failure.
   Reconnect restored a new session without resuming it. A later explicit retry
   was required. Worker events include connection failure and keepalive timeout.
3. The next eight-log trial returned after only two inventory gain, with one
   verified break. Airborne drop coordinates and missing batched block verification
   caused recovery failures. Corrected pickup to resolve the current observed
   entity, added authoritative multi-block packets, and grounded approach in
   walkable standing positions with clear sight. Inventory gain was not relabeled
   proof of an unverified break.
4. The 20-oak partial run is a real bounded limitation with depleted/inaccessible
   local candidates, not a completed 20-log request. Later birch goals were
   deliberately canceled/replaced; their last observed checkpoints remain logged.
5. The first target-disappearance attempt ended its normal 25-second interval
   before the engineer disconnected the probe. It proves only interval completion.
   A second timed attempt produced `follow_player_disappeared`.
6. The initial Python campaign had 63 passes and a five-second timeout on the
   unchanged legacy `/mario` page; a rerun also timed out. Diagnostics showed its
   YAML-loading path. No Mario implementation was changed. The final campaign,
   with the live server closed, passed that same check and all 68 checks overall.
   Earlier outputs/diagnostics remain retained.
